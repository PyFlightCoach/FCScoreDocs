# FCScore 1.0.0

**Released 24 November 2026.** Analysis version `1.0.0`, replacing `0.5.3`.

1.0.0 is the largest change to FCScore since it went online. The web app has been rebuilt, the way a flight is cut into manoeuvres and elements has been replaced, and the scoring has been reworked for every rule set. Two new rule sets, CIVA and CIVA Glider, join F3A, IMAC, IAC and IAC Glider.

Scores from 1.0.0 are not comparable with scores from 0.5.3. Read [What happens to your existing flights](#what-happens-to-your-existing-flights) first.

## Highlights

- **A new web app.** New results pages, a 3D flight viewer, downgrades grouped by type, a schedule page with Aresti sheets, progress bars, a logger check when you load a log, and a layout that works on a phone.
- **New element splitting.** Elements are now found with a hidden Markov model (HMM), which is more reliable than the dynamic time warping it replaces. A safeguard means the final result never scores worse than the starting split.
- **Better sequence splitting.** Splits between manoeuvres now sit in the middle of the line between them, and more flights are split correctly first time.
- **Several sequences per recording.** One log can be scored against up to four schedules, and if you flew a sequence more than once you can choose which repetition to score.
- **The line before a figure belongs to that figure** for IMAC, IAC and CIVA.
- **Presentation, Positioning and Airspace Control.** For IAC, CIVA and IMAC, box deductions are no longer taken off each figure. They form one sequence score from 0 to 10, weighted by its own K factor, as the rules describe.
- **CIVA and CIVA Glider rule sets**, and a reworked IAC Glider.
- **IMAC boxes by class**, from Basic to Unlimited.
- **Fairer scoring of large manoeuvres**, and templates sized to match how figures are actually flown.

## What happens to your existing flights

- **Your flights and schedules are kept.** Nothing is deleted.
- **Stored flights are re-analysed with 1.0.0.** This runs on the server after the release, newest uploads first. With several thousand stored flights it takes several days. Until a flight has been re-analysed it does not appear on the 1.0.0 leaderboards.
- **Leaderboards start almost empty and fill as the re-analysis runs.** Leaderboards only ever compare flights scored with the same analysis version, so a 0.5.3 score and a 1.0.0 score are never ranked against each other.
- **Schedules are rebuilt first.** Each schedule's manoeuvre definitions and alignment models are rebuilt for 1.0.0, most recently used schedules first. If you try to score a schedule that has not been rebuilt yet, the analysis is refused with a message asking for the schedule's manoeuvres to be updated. Try again later.
- **Competitions keep their analysis version.** A competition is tied to the version it was created with. If you try to add a flight scored with a different version, the upload now says so instead of failing.
- **The app's address does not change:** [flightcoach.org/fcscore](https://www.flightcoach.org/fcscore/).

## How scores change

The average manoeuvre score changes as shown below. These numbers come from re-scoring 356 flights (5,015 manoeuvres) from the database with both versions. The last few changes before release were checked on a subset, so the 1.0.0 column is an estimate to about ±0.1. To compare like with like, the scores include positioning deductions for every rule set.

| Rules | Flights | 0.5.3 | 1.0.0 (approx.) | Change |
| --- | ---: | ---: | ---: | ---: |
| F3A | 230 | 6.96 | 7.3 | +0.3 |
| IMAC | 76 | 4.64 | 5.3 | +0.7 |
| IAC | 50 | 7.05 | 6.85 | −0.2 |

CIVA, CIVA Glider and IAC Glider are new or substantially new in this release, and there was not enough flight data to include them.

**F3A.** Scores rise slightly. Rankings are almost unchanged: in the full test run, on every major F3A schedule (P25, P27, F25, F27, A25, A27), the order of flights by total agreed closely with 0.5.3 (rank correlation 0.95 to 0.99), and the top five were the same five flights on most of them, though not always in the same order. Most of the rise comes from better element boundaries and from fewer Track and Proportions deductions. Stall turns that 0.5.3 often scored 0 now score where the pivot is found correctly (see [Stall turns](#stall-turns)).

**IMAC.** Scores rise on every schedule, by about two thirds of a point per manoeuvre on average. The main reasons are fewer Track and Roll angle deductions, the line hand-over and better element boundaries. Positioning deductions are slightly higher because the lower classes now have smaller boxes, and they now go into the Airspace Control score instead of the figures.

**IAC.** Scores are a little lower overall. The lower categories (Primary, Sportsman, Intermediate) score about the same as before. Advanced, Unlimited and Free Known score lower, mainly because the Track rules are stricter than in 0.5.3. Loop radius deductions are back to about the 0.5.3 level, and the radius measurement no longer runs away on a few loops where 0.5.3 overcharged.

!!! note "Flight totals for IAC, CIVA and IMAC"
    For IAC, CIVA and IMAC the flight total is now the sum of K × figure score plus K × the presentation score (see [Presentation, Positioning and Airspace Control](#presentation-positioning-and-airspace-control)). Figure scores no longer include box deductions, so they are higher, and the presentation score adds a new term. Moving box deductions into one sequence score changes the ranking very little: the order by the new total and by the old per-figure total agrees closely on every schedule with more than five flights.

## Scoring changes

### Element splitting

Every figure is a series of elements: lines, loops, rolls, snaps, spins, stall turns and tail slides. Nearly every downgrade is measured on one element or on the join between two, so finding where each element starts and stops is one of the most important steps in scoring.

- **Hidden Markov model.** Element splitting now uses a hidden Markov model built from the schedule definition. At each moment it compares the measured rotation rates, roll attitude and flight path with what each element should look like, and finds the most likely path through the figure. For figures with options, or with a choice of roll direction, it works out which option you flew. Dynamic time warping, used in 0.5.3, is no longer offered. See [Element Splitting](../process/segmentation.md).
- **Models are stored with the schedule.** Each manoeuvre's model is built once, when the schedule is saved, and stored in the database. Saving, editing or deleting a schedule's manoeuvres rebuilds them automatically.
- **Score guard.** After the HMM split, an optimiser fine-tunes each boundary. Its result is kept only if it scores better than the split it started from, so optimising can never make a manoeuvre worse. If a split scores 0, the server tries again from the boundaries it was given. When stored flights are re-analysed, a manoeuvre whose new split scores worse than its previous boundaries is optimised again from those boundaries. In the test run, no manoeuvre scored lower than it did on the 0.5.3 boundaries with the 1.0.0 rules, and there were no analysis errors in 5,015 manoeuvres.
- You can still move element boundaries by hand. See [Element Segmentation](../instructions/manoeuvre_analysis/element_segmentation.md).

### Sequence splitting

- **Splits sit in the middle of the line between figures**, instead of early on it. The share of manoeuvre splits in the right place rose to about 99% for F3A and about 94% for IMAC and IAC, from 95%, 87% and 89%.
- **The last manoeuvre is no longer cut short** as often. When the final figure ends in a rolling turn or a roll, the automatic split could stop before its end. FCScore now notices when the last figure is much shorter than expected and extends it to its exit line.
- Progress is shown while a sequence is split and analysed, stage by stage.
- Manual splits can still be adjusted on the segmentation page. See [Define The Manoeuvres](../instructions/scoring/manoeuvre_segmentation.md).

### Several schedules and repetitions in one recording

- One log can be scored against **up to four schedules** at once, for example a warm-up and a competition flight. Each sequence found gets its own button in the results.
- If you **flew the same sequence more than once**, FCScore lists the repetitions and marks the one it thinks matches best. You can choose another one to score. On the test flights, choosing the repetition by hand raised the share of IMAC flights split correctly from 77% to 94%.
- Sequences that were not found, poor matches and failed segmentations are reported under the results.
- See [Several Schedules](../instructions/scoring/multiple_schedules.md).

### The line between figures (IMAC, IAC and CIVA)

The line between two figures is now scored as part of the **next** figure. Deductions measured on the exit line of one figure, such as track or roll angle errors, are counted against the figure that follows. The figure's own score keeps everything else. The results mark these deductions as counted by the next figure.

Expect IMAC and IAC figure scores to rise slightly, and line deductions to move from one figure to the next. F3A is unchanged.

### Presentation, Positioning and Airspace Control

IAC (Presentation), CIVA (Positioning) and IMAC (Airspace Control) judges give each sequence one extra mark for where the figures are placed in the box, weighted by its own K factor, as if it were an extra figure. FCScore now does the same:

- Box deductions are **no longer taken off each figure** for these rule sets. The figure pages still show them, labelled as counted in the sequence score.
- The box deductions of all the figures are added up and taken off 10 (the lowest mark is 0). The result is weighted with the schedule's K factor and added to the flight total.
- The mark is continuous. It is not rounded to the half or whole points the judges use.
- Only positioning is modelled. IAC Presentation also covers wind management and pacing, which FCScore does not measure.
- Freestyle and other schedules without a K factor keep the box deductions on the figures. F3A is unchanged.

Default K factors, filled in for each schedule from its class:

| Rules | Name | K factor |
| --- | --- | --- |
| IAC Power | Presentation | Primary 5, Sportsman 10, Intermediate 20, Advanced 30, Unlimited 40 |
| IAC Glider | Presentation | Primary 10, Sportsman 15, Intermediate 15, Advanced 20, Unlimited 25 |
| CIVA Power | Positioning | Intermediate 30, Advanced 30, Unlimited 40 (not Free programmes) |
| CIVA Glider | Positioning | Advanced 35, Unlimited 40 (not Free programmes) |
| IMAC | Airspace Control | Basic 3, Sportsman 6, Intermediate 9, Advanced 12, Unlimited 15 (not Freestyle) |

IAC Free Known ND 2026 has no class in its name and is given the Unlimited K of 40. See [Positioning Assessment](../process/box.md#where-the-box-downgrades-go).

### IMAC boxes by class

IMAC schedules now have a class, and each class has its own box. The IMAC rules do not define a box, so these sizes are FCScore estimates and will be revisited from feedback:

| Class | Width (m) | Depth (m) | Height (m) |
| --- | ---: | ---: | ---: |
| Basic | 500 | 200 | 300 |
| Sportsman | 575 | 233 | 325 |
| Intermediate | 650 | 267 | 350 |
| Advanced | 725 | 300 | 375 |
| Unlimited | 800 | 300 | 400 |

All classes have the same distance (30 m) and floor (10 m). The box deduction now reaches its full value 300 m outside the box instead of 400 m. The 3D view draws the box for the schedule's class, and its class menu switches between them.

### Manoeuvre size

Track and roll deductions on lines charge every small wobble, so a larger figure, which takes longer to fly, used to pick up more deductions for the same quality of flying. For F3A and IMAC, these deductions are now scaled by (template duration / flown duration)<sup>0.75</sup>, limited to between 0.7 and 1.4. Large figures are no longer penalised for being large, and small ones no longer gain from being small. On schedules with long figures (A25, A27, Advanced) this lowers scores by about 0.1 to 0.15 per manoeuvre, and on F25 it raises them slightly. See [Manoeuvre size](../process/intra.md#manoeuvre-size).

### Template sizes and speeds

The default size and speed of the template figures now match the median of what is actually flown:

| Rules | Speed | Loop radius | Line length |
| --- | ---: | ---: | ---: |
| F3A | 28.5 m/s | 51 m | 94 m |
| IMAC | 34 m/s | 70 m (rolling turns 157 m, rolling loops 109 m) | 99 m |
| IAC and CIVA | 60 m/s | 155 m (rolling turns 232.5 m) | 160 m |

IMAC roll and snap rates were also updated. The template sets the reference duration for the manoeuvre size scaling and the expected shape for element splitting. It does not change what counts as a correctly flown figure.

### Track and attitude visibility

A judge sees a flight path error over a path tens of metres long, but sees an attitude error from the fuselage alone, which looks very small at judging distance. The two used to share one visibility factor. Now flight path errors count a little more than before, and errors in the direction of the fuselage count less, much as roll angle errors already did. This raises IAC scores, where attitude deductions are a large part of the total, and lowers F3A and IMAC scores slightly. The numbers in [How scores change](#how-scores-change) include it. See [Visibility](../process/visibility.md).

### Centring

- **Centre manoeuvres (F3A)** are now located geometrically. Where the centre falls inside a rotating element, FCScore finds the point where the element is half way through its turn or roll, instead of half way through its time. Roll rates and turn rates are rarely constant, so this is a fairer measure. A centred rolling loop can be charged for both the loop and the roll.
- **Rolls on loops (IAC, CIVA and IMAC)** must be centred on the top or bottom of the loop. New downgrades charge rolls, snaps and pauses on a loop that are not symmetric about the apex or nadir, for round, P, Q and reversing loops alike.
- New IAC, CIVA and IMAC schedules also build their templates with the roll at the apex. Existing stored schedules keep their earlier template geometry, but the new centring downgrades apply to them.

### Stall turns

Many F3A stall turns scored 0 in 0.5.3 because the pivot was not found correctly. On the test flights, these now score 4 to 8 on average, depending on the schedule. The optimiser now measures stall turn width, height and tail slide drop in the same way as the final scoring, so it finds the pivot reliably. A few stall turns still score 0. These were checked and are genuinely flown that way.

### Inter-element comparisons

Parts of one loop that the rules link, such as the quarters of a loop interrupted by rolls, now form one loop radius comparison instead of being compared with each other in pairs. Comparisons that cannot cost anything, such as a single loop on its own or F3A speed, are no longer listed.

### Rule sets

- **CIVA and CIVA Glider** are new. They have their own downgrade lookups, glide path rules for gliders (lines and turns may be flown from level to 10° below the horizon, and a change in the angle is charged) and the CIVA Positioning score.
- **IAC Glider** now has its own downgrade descriptions and the same glide path rules, and scores rolls on lines in the same way as IAC Power.
- Every rule set has a generated [downgrade reference](../downgrades/index.md) with rulebook quotations.

### Measurement fixes

- ArduPilot logs: attitude units are scaled correctly, and the logging rate is measured from the first sample, not from boot.
- Detection of sequence direction (upwind or downwind start) is more reliable, and stored schedules record their direction.

## The web app

### Loading a flight

- **Logger check.** When you load an ArduPilot log, FCScore checks how the logger was set up (for example, whether IMU data was logged and at what rate) and the in-flight sensors (GPS quality, glitches, dropped data). It shows what it finds as a card, with a link to a [step-by-step fix](../instructions/scoring/logger_setup.md). About 70% of logs in the database do not contain IMU data, so this is worth checking.
- **Box elevation** can be read from a map, and the box map opens in a dialog over the 3D box view.
- **Progress bars** for loading, splitting and uploading, instead of a spinner.
- **AcroWRX import** takes the judging rules from the schedule, matches the database sequence by its structure, puts the box on the ground, and keeps the IAC class separate from the database category.
- Flights from AcroWRX and Flight Coach Plotter can be sent straight to FCScore (see [For partners](#for-partners)).

### Results

- **Results by type.** The manoeuvre results list downgrades grouped by what they judge (track, roll angle, roll rate, positioning, loop shape, proportions, speed, snaps, spins and stall turns), with a bar chart per group. The 3D view highlights the part of the figure each group applies to and draws a view for each: in plane, out of plane, rolls, loop shape, proportions and more. The intra, inter and box tables are still available.
- **Downgrade display.** Selecting a downgrade draws its geometry in the 3D view, shows the model at the correct roll angle, and plots the quantity the rules talk about with "measured error" and "visible error" series. Short descriptions appear in the overlay, with links to the downgrade reference.
- **Intended and corrected templates.** Next to the flown path you can show the intended template and a corrected template, fitted to the size and speed you flew, with the errors removed.
- **Line hand-over** and the **presentation score** have their own rows in the results.
- **Manoeuvre navigation.** Previous and next buttons, and playback moves on to the next manoeuvre at the end.
- **Total score tile** and percentage beside the total.
- **Comparison flights** show their stored scores next to yours.

### Viewer, leaderboards and uploads

- **Flight viewer.** Each stored flight has a page that shows the flown trajectory and the scores, with playback and analysis viewing presets. Leaderboard rows have a single **View** button.
- **Leaderboards** have the common choices in a bar above the table, more options in a popup, a compact layout on phones, and tooltips. A best-per-pilot leaderboard no longer lists a pilot twice, and deleted flights disappear straight away.
- **After an upload** you go straight to the schedule's history, sorted by upload date, where your flight is shown.
- The upload form offers to link the flight to a competition only when the competition can take it.

### Schedules

- **Schedule page** with tabs for Properties, Edit, Aresti and Figures. Aresti sheets are drawn for each schedule and can be downloaded as a PDF or an image, for both directions.
- **Schedule editor.** Parameters are managed in the left menu and edited in a popup. You can add comparison parameters, judged like rule parameters, and the popup explains combination parameters. Roll options depend on the entry, and a cross-box entry is previewed. You can start a new manoeuvre from the Aresti of a stored one, and the view follows the manoeuvres in order.
- A schedule can be created from an Aresti file through one form.
- Private schedules are included wherever you are allowed to see them.
- See [Schedules](../instructions/schedules/index.md).

### Everywhere

- A **navigation bar** with Leaderboards, Schedules and Competitions in one Database menu.
- Errors and confirmations appear as **toasts and dialogs** instead of browser alerts.
- The **help panel** shows pages from this documentation site, with a link to the full instructions.
- Layouts work on **phones**, and the first page load downloads less than half as much as before.

## Switched on after the release

These features are built and tested on the development server. They will be switched on for everyone once they have been checked on the live site:

- **F3A catalogue.** A searchable picker for F3A Unknown figures, filtered by entry height and orientation, with Aresti thumbnails.
- **Aresti images** on the schedule page and in the schedule editor.
- **Figure heights.** Derive the entry and exit heights of each figure in a schedule.
- **Uploading several sequences from one recording.** Until this is on, only one sequence per recording can be uploaded.
- **Automatic sequence layout.** Fit a schedule's figures into the box. This stays on the development server for now.

## For partners

- The address for sending flights to FCScore is `https://flightcoach.org/fcscore/flight/external?source=acrowrx` (or `source=plotter`). The older `/fcscore/flight/create/external` still works. Requests must come from a trusted origin; ask us to add yours.
- The old separate API addresses keep working until all partners have switched, and will then be removed.

## Privacy and security

- The analysis server no longer publishes usage telemetry. Usage statistics are visible to administrators only.
- Browser cookies are no longer forwarded to the analysis and database servers, the login cookie is marked secure, and the app sends standard security headers.
- AcroWRX credentials stay on the server.

## Under the hood

For developers and anyone running FCScore themselves:

- The analysis and database servers sit behind the web app, which forwards requests to them. One server hosts both the live and the development app.
- Heavy analysis requests run off the server's event loop and are limited and queued, so one large job no longer blocks other users.
- The Python packages require Python 3.15 for development. `geometry`, `FlightData`, `Schemas` and `ArdupilotLogReader` 1.0.0 are published on PyPI. FlightAnalysis is no longer published.
- The analysis version is the version of the Tuning package (`fatuning`), `1.0.0` for this release.
- Uploaded logs are stored compressed with deflate. Older LZMA files still load.

## Known issues

- **A final rolling turn can still be cut short** in IAC Advanced 2026, and a couple of IMAC flights end a little late. Check the last split on the segmentation page and move it if needed.
- **Multi-repetition logs.** In about one in five IMAC logs with repeated sequences, the best match is not the repetition that was flown for the score. Choose the repetition in the results.
- **Element splitting** still starts worse than the old boundaries on about 4% of F3A and IAC manoeuvres and 14% of IMAC manoeuvres. The score guard recovers all of them, but the analysis takes longer.
- **Box sizes and presentation weighting** for IMAC, and the presentation weighting for IAC and CIVA, are first estimates. There is no judges' data to calibrate them against yet, so feedback is welcome.
- **The last few scoring changes** (track and attitude visibility, template sizes) were checked on a subset of flights, not the full set. The score levels above are estimates.
- **IAC Presentation** does not include wind management or pacing.

Please report anything that looks wrong, with a link to the flight if you can.
